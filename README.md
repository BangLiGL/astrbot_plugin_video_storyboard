# 真正看懂B站视频

把一段视频压成“代表帧宫格 + 带时间信息的字幕或语音文本”，让机器人用有限的模型输入理解内容，再带着你为它设置的人格自然接话。

本插件由 [dsh-video-storyboard](https://github.com/SAOS-3624/dsh-video-storyboard) 的分镜理解方案移植、改写而来：将原先面向 DSH 的流程改为适合 AstrBot 的 Python 实现，并接入 AstrBot 已有的模型、语音识别、会话和人格系统。画面读取沿用原项目“用少量代表帧覆盖整段视频”的思路，聊天交互则参考 [BiliRead](https://github.com/SodaCodeSave/astrbot_plugin_biliread)，把读到的资料交回机器人，让它按当前人格表达感受、共情、接梗、吐槽或评价。

## 怎样用更少的 Token 读视频

视频先在本地做场景变化检测，在覆盖全片时间线的有限片段中选取清晰的代表帧，默认合成 **12格宫格图**。模型读取的是这一张后台图片和配套文本，无需接收数百张连续抽帧，也不只凭标题或字幕猜画面。

声音部分优先使用 B站现有字幕；没有字幕时，调用你在 AstrBot 中选择的 ASR 供应商分块转写。画面采样时间与字幕/语音片段一同交给理解模型，整理成简洁的事实资料，再注入原有聊天请求。后续追问复用已保存的资料，命中缓存时不重复下载、抽帧、转写或提取。

这样减少的是送入模型的画面数量、重复的素材输入和反复理解同一视频的开销。**具体 Token 消耗与节省幅度取决于视频内容、画面格数、文本长度和模型计费规则，不承诺固定 Token 数或节省比例。** 代表帧属于抽样，可能遗漏细节，资料不足时会明确保留不确定性。

分镜是后台的阅读材料，群友看到的是机器人带着当前人格做出的自然回应。长视频可以先生成一句同样带人格的等待提醒，再继续理解内容。

**当前版本：v0.3.0 · AstrBot ≥4.29.0、<5 · Python 实现 · MIT**

## 快速开始

1. 在 AstrBot 的插件管理中从链接安装，填写 `https://github.com/BangLiGL/astrbot_plugin_video_storyboard`；也支持本地 ZIP 安装。
2. 在 **AstrBot → 服务供应商** 配置支持图片的模型。需要识别无字幕视频时，再配置语音识别供应商。
3. 打开本插件设置，从下拉列表选择 **后台视频理解模型** 和 **语音识别供应商**。最终聊天仍由当前会话的聊天模型回复。
4. 默认在所有群启用；可填写启用群号限制范围。私聊默认关闭，可自行开启。

插件通过 `requirements.txt` 安装所需依赖，不需要填写 Node.js、FFmpeg 或 Python 程序路径，也不需要在插件里重复填写 ASR 服务地址、密钥和模型。部分 B站内容需要登录，可选填 `SESSDATA`；它属于登录凭据，请勿提交到仓库或公开日志。

## 怎么和机器人聊视频

```text
群友：看看 BV1GJ411x7h7，这段你怎么看？
机器人：[后台读取后，沿用本群的人设自然回应]

群友：[引用刚刚发出的视频] 这里为什么突然变成这样？
机器人：[读取引用视频的画面与语音，再结合上下文回答]

群友：刚才那个视频，你觉得他说得有道理吗？
机器人：[检索本群已经读过的资料继续聊]
```

支持 BV、B站视频链接、`b23.tv` 短链，以及引用的视频消息。视频链接中的 `?p=2` 会保留；不带分P时读第一P。单条消息最多理解两个视频。

引用视频需要适配器提供 `Reply.chain` 中的 `Video` 消息段，或在引用内容中提供原视频链接/BV。可以直接借用 AstrBot 数据目录内现有的本地视频；只有公网媒体地址时会按文件上限下载到临时目录，处理后删除。不会用“最近一个缓存文件”猜测引用的是哪个视频，也不会删除借用的原文件。

## 与万能解析器 parser 配合

默认开启 **与 parser 分工处理B站消息**。仅在当前会话中检测到 [Zhalslar/astrbot_plugin_parser](https://github.com/Zhalslar/astrbot_plugin_parser) 的自动解析处理器时生效：

| 发送方式 | parser 自动解析 | 本插件理解并聊天 |
| --- | --- | --- |
| 单独发送 B站链接或 `b23.tv` 短链 | 保持原行为 | 不触发 |
| 单独发送 BV 号 | 保持原行为 | 不触发 |
| 直接发送分享小卡片，包括 `@机器人 + 卡片` | 保持原行为 | 不触发 |
| `这个链接你怎么看：链接` | 跳过本条消息的自动解析 | 触发 |
| `BV号 这段好好笑`，或链接两侧夹带评论 | 跳过本条消息的自动解析 | 触发 |
| 引用 parser 发出的视频，再发文字或直接引用 | 跳过本条消息的自动解析 | 触发 |
| 引用含原视频链接/BV的消息 | 跳过本条消息的自动解析 | 触发 |
| 只发普通视频附件，没有引用或链接/BV | 本插件不改变 parser 行为 | 不主动触发 |
| 其他平台的链接 | 保持原行为 | 不介入链接解析 |

“保持原行为”不保证 parser 一定发送结果：其平台开关、白名单、重复链接防抖、仲裁和网络限制仍然生效。只有空白、括号或标点包裹的链接/BV仍按单独分享处理；额外的评论文字或表情会视为聊天意图。小卡片本身的标题、描述不会被当成用户评论。

未安装 parser、当前会话禁用了 parser，或关闭兼容开关时，本插件恢复直接读取链接、BV 和分享卡片的行为。它不修改 parser 的配置、源文件或全局工具开关；只在接管本条视频聊天消息时移除本条事件队列中的 parser `on_message`，并从本轮请求的工具副本中移除 `parse_media_url`，避免模型再次要求发送解析结果。其他消息及其他插件仍按原流程处理。

### 为什么 BV 有时解析、有时没反应？

研究 parser 的代码可以区分几种情况，而不是简单归因于“随机概率”：

- 其纯 BV 规则带有首尾锚点，要求整条匹配；完整 B站链接使用搜索匹配，因此链接两侧有文字仍可能触发。
- parser 同时按原链接、解析出的资源ID防抖；同一会话短时间重复发送可能被跳过。其所参考配置默认防抖为300秒，实际以你的设置为准。
- OneBot 群聊中还有表情仲裁。另一机器人胜出，或表情接口失败，也可能导致本机跳过解析。
- 群内 `@` 规则、平台配置，以及模型是否调用 parser 的工具，也会影响观察到的结果。

本插件通过明确分流，解决“用户带着评论聊视频时 parser 也抢着解析”的冲突。不会关闭 parser 的防抖或仲裁。兼容性参考其 `v1.6.1` 安装版本及上游提交 [`e226dfd`](https://github.com/Zhalslar/astrbot_plugin_parser/tree/e226dfd2250b4855ad67c29da7965353ad9e1379) 的消息入口；如果上游更改了处理器名称或 AstrBot 调度接口，需要重新验证。

## 长视频的人设提醒

开启 **长视频 LLM 人设提醒** 后，未命中知识缓存、且获得的时长达到阈值时，机器人会尝试先说一句需要多看一会儿的提醒。

提醒严格按 **先解析当前生效人格 → 注入人格提示词与预设对话 → 再调用当前会话聊天模型生成 → 发送** 的顺序执行。人格通过 AstrBot 的 `resolve_selected_persona()` 获取，遵循其会话强制绑定、当前对话选择及配置默认人格的优先级，不另设一个提醒角色，也不拿旧请求的人设冒充当前设置。

不能确认生效人格、人格没有可注入内容，或解析失败时，直接跳过这次提醒，继续视频理解；不会退回通用人格或固定模板。提醒不知道尚未读取的视频剧情，只提醒等待，不承诺完成时间，每条消息至多一次。

默认阈值为 **180秒**，配置中提供 **30～1800秒** 的调节条，也可以关闭提醒。短视频和缓存命中不提醒；提醒调用超时、失败或在理解结束前来不及完成时直接跳过，不阻断最终聊天。提醒是独立消息，不额外写入会话历史。

例如实测生成过：“视频有点长，我再多看一会儿哈，稍等一下～”。这只是一次模型输出的例子，实际语气随当前人设变化。

B站链接通常在取得视频元信息后、下载媒体前即可判断时长。引用的附件如果只有远程文件地址，可能需要先取得文件才能读取时长；阈值也不替代“允许理解的视频时长上限”。

## 配置一览

| 设置 | 默认值 / 行为 |
| --- | --- |
| 启用群号 | 留空为所有群；只填写群号 |
| 同时在私聊启用 | 关闭 |
| 与 parser 分工处理B站消息 | 开启；仅当前会话启用 parser 时分流 |
| 语音识别供应商 | AstrBot STT 下拉选择；留空跟随当前会话，优先使用站点字幕 |
| 后台视频理解模型 | AstrBot 模型下拉选择；留空使用全局图片描述模型或当前聊天模型 |
| B站 SESSDATA | 可选；改善需要登录的内容/字幕可用性 |
| 后台画面采样格数 | 12，可设4～16；只供后台模型读取 |
| 长视频 LLM 人设提醒 | 开启 |
| 长视频提醒阈值 | 180秒，滑条30～1800秒 |
| 允许理解的分P时长上限 | 600秒 |
| 单个下载文件大小上限 | 150 MB |
| 后台理解超时 | 240秒；并发槽内计时 |
| 视频资料缓存有效期 | 168小时；群内记忆独立保留，每群最多100条 |

视觉模型需要在 AstrBot 供应商中声明支持图片。纯文本模型可以依据已有字幕回答，但不会获得“看过画面”的标记。

## 后台怎样理解视频

```text
判断消息归属 → 复用当前会话与人设 → 检查知识缓存
  → 获取媒体信息；必要时生成人设等待提醒
  → B站取字幕/媒体，或借用引用视频缓存
  → 场景变化检测、代表帧选择、后台宫格
  → 优先站点字幕；没有字幕则调用 AstrBot STT
  → 图片模型提取中立资料，标明来源和不确定性
  → 给原聊天请求补充事实依据
  → 原聊天模型沿用人设自然接话
```

不同视频最多同时处理两个，同配置下相同视频的并发请求共用任务。画面解码与拼图在线程中执行；媒体、模型和 STT 异步调用。最终回复等待资料准备好，不会先假装已经看懂。

分镜采用全片覆盖的有限采样、场景变化辅助分段、每段候选帧清晰度选择，再合成一张后台图片。它不是逐帧观看，也没有移植原项目的所有快闪展开、局部放大或播放控制能力。图片 Token 数取决于供应商的计费规则，不承诺固定 Token 上限。

## “学进去”如何保存

资料保存在 `data/plugin_data/astrbot_plugin_video_storyboard/knowledge.sqlite3`。群记忆按 **平台 + 机器人账号 + 群号** 隔离，私聊按会话隔离。后续请求按关键词或明确的近期视频追问检索，重启后仍可继续使用。

这里保存的是可检索的视频资料，不是训练模型权重，也不会向 AstrBot 的全局知识库无差别灌入群聊内容。中立视频缓存可以复用，但群内“看过哪些视频”的记忆独立。

相同视频、视觉模型、采样配置与 ASR 配置命中缓存后不重复下载或调用模型；如果原资料直接使用 B站字幕，切换到其他已加载的 STT 供应商仍可复用原字幕结果。ASR 转写结果继续按供应商隔离，缓存原有效期不变。

处理结束、超时或取消时清理本插件创建的临时媒体、分镜和 WAV；借用的原缓存只读使用。数据库不保存媒体路径或供应商密钥。

## 边界与排错

- 风控、地区、会员、登录权限、删除和网络问题都可能导致 B站读取失败。没有证据时将失败原因交给原聊天模型，不靠标题猜剧情。
- AstrBot STT 统一接口返回文本，本插件按30秒切块，时间范围是近似块范围；站点字幕保留原时间码。背景噪声、音效和文字识别错误仍会影响理解。
- 抽样会遗漏动作、台词和画面细节；作者观点不是已证实事实。素材中的指令被当作内容，不作为机器人指令执行。
- 理解、ASR、可选提醒和最终聊天分别可能产生供应商费用。缓存可避免重复的理解成本。
- `imageio-ffmpeg` 通常随常见平台轮子提供 FFmpeg；特殊系统或架构可能仍需系统组件。安装问题查看 AstrBot 插件依赖日志，无需在本插件设置维护程序路径。
- 遇到旧版本的 `Pillow<13` 冲突，请升级；本插件不锁定低于核心的 Pillow 版本，不需要关闭 AstrBot 核心依赖保护。
- 同时启用其他视频理解/主动聊天插件时，它们仍可能独立回复；本插件的专项分流对象是 `astrbot_plugin_parser`。

## 开发与验证

```bash
python -m pip install -r requirements.txt
python -m pip install ruff
python -m unittest discover -s tests -v
ruff check .
ruff format --check .
```

测试覆盖真实合成视频解码、抽帧、FFmpeg 音频切块，以及聊天注入、人设/历史保留、群记忆隔离、缓存并发、取消清理、parser 消息分流、引用缓存只读复用和提醒时序。CI 使用 Python 3.12。

部署联调仅使用现有缓存视频与知识副本，不下载新的测试视频，也不向真实群聊发送消息。后台 STT、视觉接口已实测可用；具体人设表达和真实适配器的消息形态仍需结合群内使用验证。详见 [变更记录](CHANGELOG.md)。
