# 真正看懂B站视频

  <img src="logo.png" width="160" height="160" alt="真正看懂B站视频插件图标">
</p>

把一段视频压成“代表帧宫格 + 带时间信息的字幕或语音文本”，让机器人用有限的模型输入理解内容，再带着你为它设置的人格自然接话。

本插件由 [dsh-video-storyboard](https://github.com/SAOS-3624/dsh-video-storyboard) 的分镜理解方案移植、改写而来：将原先面向 DSH 的流程改为适合 AstrBot 的 Python 实现，并接入 AstrBot 已有的模型、语音识别、会话和人格系统。画面读取沿用原项目“用少量代表帧覆盖整段视频”的思路，聊天交互则参考 [BiliRead](https://github.com/SodaCodeSave/astrbot_plugin_biliread)，把读到的资料交回机器人，让它按当前人格表达感受、共情、接梗、吐槽或评价。

## 怎样用更少的 Token 读视频

视频先在本地检测画面变化，在覆盖全片的时间线上为变化密集的片段分配更多采样，再从各区间挑选清晰、尽量避开近黑画面的代表帧。默认总共采样 **12格**，按实际可读尺寸拆成一张或多张后台宫格图；**每张默认不超过120万像素，每个视频默认最多4张**。模型读取这些有上限的图片和配套文本，无需接收数百张连续抽帧，也不只凭标题或字幕猜画面。

声音部分按 **B站字幕 → 视频内嵌文本字幕 → 有效转写缓存 → AstrBot ASR** 的顺序取得文字；字幕提取与语音转写会和画面扫描并行进行。画面采样时间与字幕/语音片段一同交给理解模型，整理成简洁的事实资料，再注入原有聊天请求。后续追问复用已保存的资料，命中缓存时不重复下载、抽帧、转写或提取。

这样减少的是送入模型的画面数量、重复的素材输入和反复理解同一视频的开销。**具体 Token 消耗与节省幅度取决于视频内容、画面格数、文本长度和模型计费规则，不承诺固定 Token 数或节省比例。** 代表帧属于抽样，可能遗漏细节，资料不足时会明确保留不确定性。

分镜是后台的阅读材料，群友看到的是机器人带着当前人格做出的自然回应。长视频可以先生成一句同样带人格的等待提醒，再继续理解内容。

**当前版本：v0.6.0 · AstrBot ≥4.29.0、<5 · Python 实现 · MIT / 部分模块 Apache-2.0**

## 快速开始

1. **插件市场安装**：打开 **AstrBot → 插件管理 → 插件市场**，搜索“真正看懂B站视频”后安装。如果市场索引暂未同步、搜索不到，可选择**从链接安装**，填写 `https://github.com/BangLiGL/astrbot_plugin_video_storyboard`；也支持本地 ZIP 安装。
2. 在 **AstrBot → 服务供应商** 配置支持图片的模型。需要识别无字幕视频时，再配置语音识别供应商。
3. 打开本插件设置，从下拉列表选择 **后台视频理解模型** 和 **语音识别供应商**。最终聊天仍由当前会话的聊天模型回复。
4. 默认在所有群启用；可填写启用群号限制范围。私聊默认关闭，可自行开启。

插件通过 `requirements.txt` 安装所需依赖，不需要填写 Node.js、FFmpeg 或 Python 程序路径，也不需要在插件里重复填写 ASR 服务地址、密钥和模型。部分 B站内容需要登录，可选填 `SESSDATA`；它属于登录凭据，请勿提交到仓库或公开日志。

当前 `metadata.yaml` 的 `support_platforms` 保持注释，允许其他适配器尝试加载；这不代表已经验证所有平台和系统架构。已有联调主要在 **aiocqhttp（OneBot v11）** 完成。其他平台能否读取引用视频，取决于适配器是否提供原消息链和可访问的媒体地址；遇到问题请在 Issue 中附上 AstrBot 版本、适配器名称、消息类型与脱敏日志。

## 怎么和机器人聊视频

```text
群友：看看 BV1GJ411x7h7，这段你怎么看？
机器人：[后台读取后，沿用本群的人设自然回应]

群友：[引用刚刚发出的视频] 这里为什么突然变成这样？
机器人：[读取引用视频的画面与语音，再结合上下文回答]

群友：刚才那个视频，你觉得他说得有道理吗？
机器人：[检索本群已经读过的资料继续聊]
```

支持 BV、B站视频链接、`b23.tv` 短链，以及引用的视频消息。视频链接中的 `?p=2` 会保留；不带分P时读第一P。单条消息最多理解两个视频。

引用视频需要适配器提供 `Reply.chain` 中的 `Video` 消息段，或在引用内容中提供原视频链接/BV。可以直接借用 AstrBot 数据目录内现有的本地视频；只有公网媒体地址时会按文件上限下载到临时目录，处理后删除。不会用“最近一个缓存文件”猜测引用的是哪个视频，也不会删除借用的原文件。

## 与万能解析器 parser 配合

默认开启 **与 parser 分工处理B站消息**。仅在当前会话中检测到 [Zhalslar/astrbot_plugin_parser](https://github.com/Zhalslar/astrbot_plugin_parser) 的自动解析处理器时生效：

| 发送方式 | parser 自动解析 | 本插件理解并聊天 |
| --- | --- | --- |
| 单独发送 B站链接或 `b23.tv` 短链 | 保持原行为 | 不触发 |
| 单独发送 BV 号 | 保持原行为 | 不触发 |
| 直接发送分享小卡片，包括 `@机器人 + 卡片` | 保持原行为 | 不触发 |
| `这个链接你怎么看：链接` | 跳过本条消息的自动解析 | 触发 |
| `BV号 这段好好笑`，或链接两侧夹带评论 | 跳过本条消息的自动解析 | 触发 |
| 引用 parser 发出的视频，再发文字或直接引用 | 跳过本条消息的自动解析 | 触发 |
| 引用含原视频链接/BV的消息 | 跳过本条消息的自动解析 | 触发 |
| 只发普通视频附件，没有引用或链接/BV | 本插件不改变 parser 行为 | 不主动触发 |
| 其他平台的链接 | 保持原行为 | 不介入链接解析 |

“保持原行为”不保证 parser 一定发送结果：其平台开关、白名单、重复链接防抖、仲裁和网络限制仍然生效。只有空白、括号或标点包裹的链接/BV仍按单独分享处理；额外的评论文字或表情会视为聊天意图。小卡片本身的标题、描述不会被当成用户评论。

未安装 parser、当前会话禁用了 parser，或关闭兼容开关时，本插件恢复直接读取链接、BV 和分享卡片的行为。它不修改 parser 的配置、源文件或全局工具开关；只在接管本条视频聊天消息时移除本条事件队列中的 parser `on_message`，并从本轮请求的工具副本中移除 `parse_media_url`，避免模型再次要求发送解析结果。其他消息及其他插件仍按原流程处理。

### 为什么 BV 有时解析、有时没反应？

研究 parser 的代码可以区分几种情况，而不是简单归因于“随机概率”：

- 其纯 BV 规则带有首尾锚点，要求整条匹配；完整 B站链接使用搜索匹配，因此链接两侧有文字仍可能触发。
- parser 同时按原链接、解析出的资源ID防抖；同一会话短时间重复发送可能被跳过。其所参考配置默认防抖为300秒，实际以你的设置为准。
- OneBot 群聊中还有表情仲裁。另一机器人胜出，或表情接口失败，也可能导致本机跳过解析。
- 群内 `@` 规则、平台配置，以及模型是否调用 parser 的工具，也会影响观察到的结果。

本插件通过明确分流，解决“用户带着评论聊视频时 parser 也抢着解析”的冲突。不会关闭 parser 的防抖或仲裁。兼容性参考其 `v1.6.1` 安装版本及上游提交 [`e226dfd`](https://github.com/Zhalslar/astrbot_plugin_parser/tree/e226dfd2250b4855ad67c29da7965353ad9e1379) 的消息入口；如果上游更改了处理器名称或 AstrBot 调度接口，需要重新验证。

## 与陪伴及其他聊天增强插件配合

默认 **聊天触发协作模式 = `auto`**。独立使用时，发现符合条件的视频消息会唤醒 AstrBot 的原生聊天管线，由核心选择会话、人格、聊天模型并发送回复；本插件不再独立创建 `request_llm`，也不新建会话。

检测到当前事件启用 [我会永远陪着你（private_companion）](https://github.com/menglimi/astrbot_plugin_private_companion) 的消息处理器时，本插件只记录视频引用，让陪伴插件按自己的接话、唤醒、收口与沉默策略决定是否回复。只有原流程真正进入聊天请求后才读取视频、按需提醒并补充资料。**陪伴插件决定不接话时，本插件不会因为出现 BV 号就额外回复；需要聊视频时按原设置 @机器人、使用唤醒词或引用对话。**

使用其他接管聊天的插件时，可把协作模式设为 **`passive`**：始终只为已发起的聊天请求补充资料，不主动唤醒。自动模式仍保留其他插件已有的停止事件、抑制默认请求和已发送标记，不恢复它们已取消的回复。

视频证据在较晚的 LLM 请求钩子中，以独立 `extra_user_content_parts` 内容块加入：不替换原始用户 Prompt、人格系统提示、历史或其他插件的附加内容。相同请求不会重复注入；同一事件重建请求时可复用已准备的证据。parser 的专项分工继续生效，仅处理本条视频对应的解析器监听器与工具副本。

已使用服务器 AstrBot **4.29.3** 的实际聊天管线及 private_companion **6.5.6** 的提示词注入计划做隔离验证：沉默时零请求，接话时单次原生请求，提示词整理后保留视频证据。**7.x 仅检查上游原生聊天接入源码，未完整运行联调。**不同版本、其他插件自行调用模型/直接发送消息等独立行为，仍需按具体实现验证；`passive` 是其他聊天控制插件的通用协作入口。本插件不会修改其他插件的源码、配置、全局工具或模型路由。

## 长视频等待提醒

开启 **长视频等待提醒** 后，已有聊天请求读取未命中知识缓存、且时长达到阈值的视频时，机器人会尝试先发一句等待提醒。可选择两种方式：

| 提醒方式 | 配置内容 | 行为 |
| --- | --- | --- |
| `llm`：人设 LLM 提醒，默认 | **LLM提醒自定义Prompt** | 注入当前人格后让当前会话聊天模型自由生成；最多取4000字Prompt，发送结果最多120字 |
| `fixed`：固定文本 | **长视频固定提醒文本** | 直接发送配置的文字，不经过LLM改写，不解析人格；最多500字，留空不发送 |

两种文本都支持 `{duration_seconds}`（总秒数）和 `{duration_minutes}`（分钟，1位小数）。只替换这两个占位符，其他花括号或JSON原样保留。例如：

```text
LLM Prompt：请沿用当前人格，俏皮地提醒对方：这段视频有{duration_minutes}分钟，需要多看一会儿。只说一句。
固定文本：这段视频约{duration_minutes}分钟，我先认真看一下，稍等～
```

LLM方式严格按 **先解析当前生效人格 → 注入人格提示词与预设对话 → 再调用当前会话聊天模型生成 → 发送** 的顺序执行。人格通过 AstrBot 的 `resolve_selected_persona()` 获取；当前请求已包含该人格时，也会沿用请求中已准备的人格增强提示。不另设一个提醒角色，也不拿旧请求的人设冒充当前设置。自定义Prompt仍保留“尚在读取、不能假装看完或编造完成时间”的边界。

LLM方式不能确认生效人格、人格没有可注入内容或解析失败时，跳过这次提醒，继续理解，不自动切换固定文本。固定方式不要求人格可用，也不会因空文本或错误模式偷偷调用LLM。每条消息至多提醒一次；其他插件已停止事件时不生成、不发送提醒。

默认阈值为 **180秒**，配置中提供 **30～1800秒** 的调节条，也可以关闭提醒。短视频和缓存命中不提醒；提醒超时、失败或理解已结束时直接跳过，不阻断最终聊天。提醒通过当前事件的发送接口投递，保留其他插件已有的发送包装，不由本插件额外写入会话历史。

例如实测生成过：“视频有点长，我再多看一会儿哈，稍等一下～”。这只是一次模型输出的例子，实际语气随当前人设变化。

B站链接通常在取得视频元信息后、下载媒体前即可判断时长。引用的附件如果只有远程文件地址，可能需要先取得文件才能读取时长；阈值也不替代“允许理解的视频时长上限”。

## 配置一览

| 设置 | 默认值 / 行为 |
| --- | --- |
| 启用群号 | 留空为所有群；只填写群号 |
| 同时在私聊启用 | 关闭 |
| 聊天触发协作模式 | `auto`；检测陪伴插件时交由其决定接话，其他聊天控制插件可用 `passive` |
| 与 parser 分工处理B站消息 | 开启；仅当前会话启用 parser 时分流 |
| 语音识别供应商 | AstrBot STT 下拉选择；留空跟随当前会话，优先使用站点字幕 |

| B站 SESSDATA | 可选；改善需要登录的内容/字幕可用性 |
| 后台画面采样格数 | 总共12，可设4～32；只供后台模型读取 |
| 分镜可读性需求 | `scene`；`shot` 看镜头构图、`scene` 看场景细节、`text` 为文字预留更大格子；不保证能读清小字 |
| 每张分镜像素预算 | 120万，可设20万～200万；包含边距与时间标签 |
| 每张分镜最多格数 | 0为按可读性自动规划；可手动设1～16，实际渲染遵守此上限 |
| 每个视频最多分镜图数 | 4，可设1～6；必要时减少总格数并明确记录证据缺口 |
| B站视频下载清晰度 | `720p`，可选 `360p` / `720p` / `1080p`；优先选择不高于目标的可用流，无合适低档时取最低可用档 |
| 长视频等待提醒 | 开启 |
| 长视频提醒方式 | `llm`；可选 `fixed`，旧配置默认沿用LLM方式 |
| LLM提醒自定义Prompt | 按当前人格生成一句简短提醒；支持时长占位符 |
| 长视频固定提醒文本 | “这段视频有点长，我需要多看一会儿，稍等一下～”；支持时长占位符 |
| 长视频提醒阈值 | 180秒，滑条30～1800秒 |
| 允许理解的分P时长上限 | 600秒 |
| 单个下载文件大小上限 | 150 MB |
| 后台理解超时 | 240秒；并发槽内计时 |
| 视频资料缓存有效期 | 168小时；群内记忆独立保留，每群最多100条 |

视觉模型需要在 AstrBot 供应商中声明支持图片。纯文本模型可以依据已有字幕回答，但不会获得“看过画面”的标记。

## 后台怎样理解视频

```text
判断消息归属 → 复用当前会话与人设 → 检查知识缓存
  → 获取媒体信息；必要时生成人设等待提醒
  → B站取字幕/媒体，或借用引用视频缓存
  → 并行准备画面与文字：
      画面：连续低分辨率扫描 → 切镜/渐变检测 → 分批取帧 → 后台宫格
      文字：站点字幕 → 内嵌文本字幕 → 有效转写缓存 → AstrBot STT
  → 图片模型提取中立资料，标明来源和不确定性
  → 给原聊天请求补充事实依据
  → 原聊天模型沿用人设自然接话
```

不同视频最多同时处理两个，同配置下相同视频的并发请求共用任务。画面解码与拼图在线程中执行；媒体、模型和 STT 异步调用。最终回复等待资料准备好，不会先假装已经看懂。

v0.5.0 选择性同步上游截至 **v0.6.2** 的后台能力。切镜检测保留原始分数确定阈值，对暗场和上下黑边做比较值补偿，结合约0.4秒的跨帧变化识别渐变；持续镜头运动和规律两帧动画受到误检抑制。按变化密度分配采样，在区间内优先选择完整镜头中的清晰候选帧，静态区间仍保留覆盖。

解码改用随 `imageio-ffmpeg` 提供的 FFmpeg 连续扫描和稀疏窗口批量取帧，减少逐帧跳转。扫描画面仅64×36，最高24帧/秒、最多14400帧；长视频会降低扫描率并提示可能漏过极短镜头。候选帧每批最多8个时间点、跨度最多12秒，解码像素缓冲按每批32 MiB限制。这里的上限约束扫描与候选像素缓冲，不代表整个 AstrBot 进程的内存上限。

每格只是一帧，`frame_at` 来自实际解码的帧时间戳（PTS）；区间范围和帧时刻分别标注，多图额外标明整片的绝对时间范围与页码，不能把单帧当作该段连续录像。扫描、取帧与字幕读取设置超时，取消时停止相应子进程并回收临时文件。

内嵌字幕目前尝试第一条字幕轨，能转换为文本时读取其内容，不含画面硬字幕 OCR 或图形字幕识别。没有音轨、音轨取得失败、未配置 ASR、ASR 失败与 ASR 返回空文本会分别记录；有音轨不代表有人声，没有转写也不能推断没有台词。有 B站字幕时会省去独立音轨下载，并明确标记为“有提供、未下载”。

自动布局会兼顾格子尺寸和图数上限；手动塞入过多格子、原视频分辨率不足或近黑画面都会作为限制交给模型，不能靠放大低清源冒充可读文字。`text` 是尺寸目标，不是额外的 OCR 服务。下载清晰度与拼图像素预算分别控制源素材质量和模型输入大小，提高前者也可能增加下载流量与临时占用，仍受文件大小上限约束。

本插件移植的是适合聊天的后台采样和证据组织流程，本版保持原有宫格布局与配置，不引入上游的新一代动态大小拼图、DSH/harness 集成或 WebUI。尚未提供浏览器播放器、交互式局部放大、快闪序列展开或字幕条专门拼接工具。图片 Token 数取决于供应商的计费规则，不承诺固定 Token 上限。

## “学进去”如何保存

资料保存在 `data/plugin_data/astrbot_plugin_video_storyboard/knowledge.sqlite3`。群记忆按 **平台 + 机器人账号 + 群号** 隔离，私聊按会话隔离。后续请求按关键词或明确的近期视频追问检索，重启后仍可继续使用。

这里保存的是可检索的视频资料，不是训练模型权重，也不会向 AstrBot 的全局知识库无差别灌入群聊内容。中立视频缓存可以复用，但群内“看过哪些视频”的记忆独立。

相同视频、视觉模型、采样配置与 ASR 配置命中缓存后不重复下载或调用模型；如果原资料使用 B站字幕或内嵌文本字幕，切换到其他已加载的 STT 供应商仍可复用原字幕结果。ASR 转写结果继续按供应商隔离，缓存原有效期不变。

v0.4.0 新增独立 ASR 文本缓存：调整分镜格数、像素预算、清晰度或视觉模型后，仍可复用同一视频的有效转写。供应商有效配置（包括模型、语言、热词等）变化会使转写缓存失效；只保存配置摘要作为缓存键，不保存原始配置或密钥。转写按同一缓存有效期过期，读取不续期，最多保留200条。这个缓存不免除重新分析时获取源视频的需要。

v0.5.0 将完整理解结果缓存键升级到 v4，旧版完整结果首次重新请求时会重新分析一次，已有群记忆和独立 ASR 缓存继续保留。数据库结构沿用 v0.4.0，无需清库。有效转写缓存可在本次音轨获取失败时继续提供历史文字证据。不同采样配置下同时首次分析同一视频时，仍可能发生重复转写。

处理结束、超时或取消时清理本插件创建的临时媒体、分镜和 WAV；借用的原缓存只读使用。数据库不保存媒体路径或供应商密钥。

## 边界与排错

- 风控、地区、会员、登录权限、删除和网络问题都可能导致 B站读取失败。没有证据时将失败原因交给原聊天模型，不靠标题猜剧情。
- AstrBot STT 统一接口返回文本，本插件按30秒切块，时间范围是近似块范围；站点字幕保留原时间码。背景噪声、音效和文字识别错误仍会影响理解。
- 抽样会遗漏动作、台词和画面细节；作者观点不是已证实事实。素材中的指令被当作内容，不作为机器人指令执行。
- 理解、ASR、可选提醒和最终聊天分别可能产生供应商费用。缓存可避免重复的理解成本。
- `imageio-ffmpeg` 通常随常见平台轮子提供 FFmpeg；特殊系统或架构可能仍需系统组件。安装问题查看 AstrBot 插件依赖日志，无需在本插件设置维护程序路径。
- 遇到旧版本的 `Pillow<13` 冲突，请升级；本插件不锁定低于核心的 Pillow 版本，不需要关闭 AstrBot 核心依赖保护。
- 同时启用其他视频理解插件时，它们仍可能独立分析或发送结果；本插件专项分流 parser，自动协作 private_companion，其他聊天控制插件可选 `passive`。不保证能阻止其他插件自己创建请求或直接发送消息。
